## 1. 모델이 하는 일

사용자가 음식을 선택하면, **식사 후 120분 동안 5분 간격으로 혈당이 어떻게 변할지** 예측합니다.

```
입력: 김밥 (탄수화물 66g, 단백질 8g, 지방 6g), 식전 혈당 110 mg/dL, 점심 12시
출력: [115, 122, 131, 140, 148, 155, 160, 163, 162, 159, ...]  ← 5분마다 24개 혈당값
```

이 예측값을 바탕으로 앱에서 혈당 곡선 그래프를 보여주고, 음식별 혈당 영향을 S/A/B/C/D 등급으로 안내합니다.

## 2. 학습에 사용한 데이터

### 데이터셋: Shanghai T2DM Dataset

중국 상하이에서 수집된 **2형 당뇨(T2DM) 및 정상인 환자 데이터**입니다.

| 항목 | 내용 |
|------|------|
| 출처 | 상하이 당뇨 연구 데이터 (공개 데이터셋) |
| 대상 | 2형 당뇨 환자 + 정상인 (1형 당뇨 제외) |
| 측정 방식 | CGM (연속혈당측정기) — 15분 간격으로 혈당 자동 측정 |
| 기록 내용 | 식사 시각, 음식 영양소, 식전/식후 혈당 변화 |

### 왜 이 데이터를 썼나?

식사-혈당 반응을 연구한 공개 임상 데이터 중 **음식 영양소(탄수화물·단백질·지방·식이섬유)와 식후 혈당 곡선이 함께 기록된 드문 데이터**입니다.

### 학습/검증/테스트 분할

데이터는 **사람 단위**로 분리합니다. 같은 사람이 학습과 테스트에 동시에 들어가지 않도록 합니다.

```
전체 환자 → 70% 학습 / 15% 검증 / 15% 테스트
```

## 3. 모델 입력 — 어떤 정보를 받는가

모델은 아래 **11가지 정보**를 숫자로 받아서 혈당을 예측합니다.

| 번호 | 입력값 | 설명 |
|------|--------|------|
| 1 | **탄수화물 (g)** | 음식의 탄수화물 함량. 혈당에 가장 직접적인 영향 |
| 2 | **단백질 (g)** | 단백질은 혈당 상승을 일부 억제 |
| 3 | **지방 (g)** | 지방은 소화를 늦춰 혈당 피크 시점을 늦춤 |
| 4 | **식이섬유 (g)** | 혈당 상승 속도를 낮춤 |
| 5 | **열량 (kcal)** | 총 에너지량 |
| 6 | **식전 혈당 (mg/dL)** | 식사 직전 측정한 혈당값. 시작점 |
| 7 | **식사 시각 (sin)** | 아침/점심/저녁 등 하루 중 시간대. 인체 일주기 반영 |
| 8 | **식사 시각 (cos)** | 시각 정보를 원형으로 표현하기 위해 2개 숫자로 분리 |
| 9 | **당뇨 유형** | 정상(0) / 1형 당뇨(1) / 2형 당뇨(2) |
| 10 | **탄수화물 비율** | 전체 영양소 중 탄수화물 비중 |
| 11 | **단백질+지방 합계** | 혈당 상승 억제 효과의 총량 |

> **참고**: 식사 시각을 sin/cos 두 개로 표현하는 이유 — 23:50과 00:10은 10분 차이지만 숫자로는 23.8과 0.2로 멀리 떨어져 있습니다. 원형 표현을 쓰면 이런 문제가 없어집니다.

## 4. 모델 구조 — 어떻게 예측하는가

### 모델명: ShanghaiLSTM (coef=1.5)

두 단계로 예측합니다.

### 4-1. 선형 Prior (뼈대 곡선)

먼저 영양소 공식으로 **"이 음식이면 대략 이 정도 혈당이 오르겠다"** 는 기본 예측을 계산합니다.

```
예상 피크 상승량 = 10 + 탄수화물 × 1.5 - 식이섬유 × 1.5 - 지방 × 0.3 - 단백질 × 0.2
```

이 공식은 Zewei et al. (2015) 임상 연구의 계수를 기반으로 하고, 피크 시점·하강 속도를 조합해 24개 시점 곡선으로 만듭니다.

### 4-2. LSTM 잔차 보정

LSTM 신경망은 **선형 공식이 틀린 만큼(잔차)을 학습**합니다.

```
최종 예측 = 선형 공식 예측 + LSTM이 학습한 보정값
```

이 방식의 장점은 LSTM이 0에서부터 전부 학습할 필요 없이, **선형 공식이 잡아주지 못하는 개인차·패턴만 집중해서 배운다**는 것입니다.

### LSTM 내부 구조

```
입력 (11개 숫자)
    ↓
Encoder (당뇨 유형 Embedding + Linear layer)
    ↓
LSTMCell (시간 단계별 반복)  ← 시각 정보(step embedding) 추가 입력
    ↓
출력 (24개 혈당 변화량)
```

## 5. 학습 방식

### Peak-Weighted Loss

혈당 피크 구간(30~90분)의 오차에 **3배 가중치**를 줍니다. 피크가 얼마나 높이 올라가는지가 실제 사용자에게 가장 중요한 정보이기 때문입니다.

```
일반 구간 오차 × 1배
피크 구간(30~90분) 오차 × 3배
```

### 조기 종료 (Early Stopping)

검증 데이터 성능이 30 에폭 이상 개선되지 않으면 학습을 멈춥니다. 과적합을 방지합니다.

### 정규화

모든 입력값은 표준화(StandardScaler)를 거칩니다. 탄수화물 70g과 혈당 150 mg/dL처럼 단위가 전혀 다른 숫자들을 같은 스케일로 맞춥니다.

## 6. 실험 및 모델 선택 과정

여러 실험을 거쳐 최종 모델을 선정했습니다.

### 실험 1: 탄수화물 계수(carb_coef) 비교

선형 공식의 탄수화물 가중치를 1.2 / 1.5 / 2.0으로 바꿔가며 비교했습니다.

| 계수 | MAE 평균 | 탄수화물 민감도 | 비고 |
|------|---------|--------------|------|
| 1.2 | 31.03 mg/dL | 3.4 mg/dL | 탄수화물 차이 반영 약함 |
| **1.5** | **31.28 mg/dL** | **9.9 mg/dL** | **✅ 채택** |
| 2.0 | 30.28 mg/dL | 3.9 mg/dL | MAE는 좋으나 탄수화물 민감도 낮음 |

> **탄수화물 민감도**: 고탄수(70g) vs 저탄수(15g) 음식을 넣었을 때 예측 피크 차이. 숫자가 클수록 탄수화물 양에 따라 다른 예측을 함.

**coef=2.0이 MAE가 가장 낮지만 coef=1.5를 채택한 이유**: coef=2.0은 탄수화물 민감도가 오히려 낮아져서 (3.9), 고탄수/저탄수 음식을 거의 같게 예측하는 문제가 생겼습니다. coef=1.5는 탄수화물 양에 따라 의미 있는 차이를 보여줍니다 (9.9).

### 실험 2: 식전 혈당 slope feature 추가

식사 직전 45분간 혈당 변화 추세(오르고 있는지, 내리고 있는지)를 feature로 추가해봤습니다.

| 모델 | MAE 평균 |
|------|---------|
| 기본 (11 feature) | 31.28 mg/dL |
| slope 추가 (12 feature) | 31.01 mg/dL |

성능 개선이 미미(0.27 mg/dL)하고, 실제 서비스에서 slope를 실시간 계산하는 복잡도가 추가되어 미적용 결정.

## 7. 최종 성능

### 평가 기준

- **MAE (Mean Absolute Error)**: 예측값과 실제값의 평균 차이. 낮을수록 좋음.
- **RMSE**: MAE보다 큰 오차에 더 민감한 지표. 낮을수록 좋음.
- 단위: mg/dL (혈당 단위)

### 현재 모델 성능 (T2DM 테스트셋 339건 기준)

| 예측 시점 | MAE | RMSE | CEG A+B |
|----------|-----|------|---------|
| 식후 5분 | 8.8 mg/dL | 12.0 mg/dL | 98.2% |
| 식후 30분 | 33.6 mg/dL | 43.1 mg/dL | 97.3% |
| 식후 60분 | 34.2 mg/dL | 45.1 mg/dL | 95.6% |
| 식후 120분 | 29.5 mg/dL | 39.4 mg/dL | 94.4% |
| **피크 오차** | **31.2 mg/dL** | — | — |

> 출처: `eval/t2dm_compare/results.json`

### 성능 해석

30분 MAE가 33.6 mg/dL인 것은 "실제 혈당 160인데 예측은 126~194 사이"라는 의미입니다. 혈당 예측은 **개인차가 매우 커서** 전 세계적으로도 어려운 문제입니다. 같은 음식을 같은 사람이 먹어도 날마다 혈당이 다르게 반응하기 때문입니다.

현재 모델은 **개인화 데이터가 없는 상태의 초기 예측**으로, 개인화가 쌓일수록 정확도가 높아집니다.

## 8. 개인화 기능

사용자가 앱을 쓰면서 실제 혈당 데이터가 쌓이면, 그 사람 전용 모델로 조정됩니다.

### 개인화가 필요한 이유

같은 탄수화물 66g이어도:
- 인슐린 감수성이 높은 사람 → 혈당이 많이 안 오름
- 위 배출이 느린 사람 → 피크가 90분 뒤에 옴
- 기저 혈당이 높은 사람 → 시작점이 다름

기본 모델은 "평균적인 T2DM 환자"를 기준으로 만들어졌습니다. 개인화는 이 기본 모델을 실제 사용자 반응에 맞게 미세 조정합니다.

### 개인화 방식

1. 사용자의 식사 기록 + 실제 식후 혈당 곡선 데이터 수집 (최소 10건)
2. 기본 모델을 그 사람 데이터로 추가 학습 (Fine-tuning, 30 에폭)
3. 기본 모델보다 성능이 개선된 경우에만 저장 (자동 폐기 로직)
4. 이후 예측 시 개인화 모델 자동 사용 (`lstm_meal_personalized_{user_id}.pt`)

### 현재 구현 상태

- **AI 서버 엔드포인트**: 구현 완료 (`POST /inference/glucose/personalize`)
- **백엔드 연결**: **미연결** — 백엔드가 아직 이 엔드포인트를 호출하지 않음
- 코드: `ai/app/glucose/personalize.py`

## 9. 서비스 연결 흐름

```
[사용자 앱]
    ↓  음식 선택 (김밥)
[Spring Boot 백엔드]
    ↓  영양소 + 사용자 정보 조합
[AI 서버 FastAPI]
    ↓  ShanghaiLSTM 추론
    ↓  선형 prior 계산 + LSTM 잔차 합산
    ↓  절대 혈당값 24개 반환
[Spring Boot 백엔드]
    ↓  DB 저장 + 응답 가공
[사용자 앱]
    ↓  혈당 곡선 그래프 표시
```

### 폴백(Fallback) 처리

모델 파일이 없거나 오류 시 자동으로 대안 예측:
1. **ShanghaiLSTM** (주 모델)
2. **Stage2 XGBoost** (LSTM 파일 없을 때)
3. **휴리스틱 더미** (전부 실패 시 — "탄수화물 × 0.6 = 피크 상승")
