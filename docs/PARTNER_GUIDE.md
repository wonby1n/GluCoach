# GluCoach 서비스 안내서

> 본 문서는 GluCoach 서비스를 처음 접하는 비개발 의사결정자께서 약 10분 안에 "이 서비스가 무엇을 풀고, 누구에게, 어떤 가치를 주는가"를 파악하실 수 있도록 정리한 안내서입니다.
> 작성: SSAFY 14기 자율 프로젝트팀 (S309) · 2026. 05

---

## 한 줄 요약

> **"내 혈당과 식사가 매일 어떻게 맞물리는지 한 화면에서 확인하고, 다음 끼니를 더 안전하게 고르도록 도와주는 AI 당뇨 케어 동반자."**

GluCoach는 혈당 추이, 식단 기록, AI 비서와의 대화를 **한 대시보드 안**에 통합한 안드로이드 앱입니다. 사용자는 앱을 열어 자신의 혈당 그래프 위에 오늘 먹은 식사를 겹쳐 보고, AI 비서 "키키"와 대화하며 다음 식사를 결정합니다. 여기에 — 어떤 앱에서든 음식 이름을 입력하면 즉시 혈당 영향 등급을 띄워주는 자체 키보드와, 운전 중에도 호출 가능한 음성 비서가 일상의 빈틈을 메워줍니다.

---

## 1. 왜 만들었나 — 우리가 풀려는 문제

### 1-1. 당뇨와 혈당 관리는 더 이상 소수의 문제가 아닙니다

- 국내 30세 이상 성인 6명 중 1명이 당뇨, 4명 중 1명이 당뇨 전단계로 분류됩니다 (대한당뇨병학회 Diabetes Fact Sheet 2024 기준).
- 임신성 당뇨, 비만 다이어트 중 혈당 관리, 노년기 만성질환 관리 등 "혈당을 신경 써야 하는 일상"의 범위는 빠르게 확대되고 있습니다.
- 그러나 사용자 입장에서 가장 어려운 것은 "검사"가 아니라 **"매끼 식사 직전, 무엇을 먹을지 결정하는 그 순간"** 입니다.

### 1-2. 기존 헬스케어 앱이 닿지 않는 영역

| 기존 접근                | 한계                                                                     |
| ------------------------ | ------------------------------------------------------------------------ |
| 수기 식단 다이어리       | 매일 적는 부담이 크고, 누적 데이터를 분석해 통찰로 돌려주지 못함         |
| 범용 식단 트래커 앱      | 일반인 칼로리 위주로 설계되어 **당뇨 특화 등급·혈당 예측이 없음**        |
| 의사·영양사 상담         | 시간·비용 진입장벽. 1년에 몇 번뿐 — 매 끼니 결정에는 닿지 않음           |
| 연속혈당측정기(CGM) 단독 | 측정값은 보여주지만 "그래서 지금 뭘 먹어야 하는가"에 대한 답은 주지 않음 |

**핵심 통찰**: 음식 선택은 보통 카카오톡 채팅 중에 일어납니다 — "오늘 점심 뭐 먹지?", "마라탕 ㄱ?", "라면 콜". 이 결정의 순간에 들어가야 의미 있는 개입이 가능합니다.

### 1-3. GluCoach가 잡으려는 두 시간대

GluCoach는 사용자의 하루를 **"하루를 되돌아보는 시간"**과 **"식사 직전의 결정 순간"** 두 시간대에서 동시에 돕습니다.

```
[하루의 끝/시작]                       [식사 직전의 결정 순간]
앱 메인 대시보드                        카톡 단톡방, 운전 중, 음식점 앞
어제의 혈당 곡선 위에                   "마라탕?", "라면 어때?", "뭐 먹지?"
오늘 먹은 식사를 겹쳐 보고,             그 1초의 순간에
AI 비서가 패턴을 짚어줌                  키보드/음성/앱이 즉시 등급·예측·추천을 띄움
(누적 패턴 학습)                        (의사결정 보조)
```

전자는 **꾸준한 자기 추적**을, 후자는 **순간의 더 나은 선택**을 만듭니다. 기존 헬스케어 앱이 잘 다루지 못했던 두 번째 시간대를 GluCoach는 키보드·음성 비서를 통해 자연스럽게 사용자의 일상으로 들어갑니다.

## 2. 무엇이 다른가 — 핵심 가치 제안

### ① 키보드 안에 들어간 AI

GluCoach의 가장 큰 차별점은 **안드로이드 시스템 키보드(IME)** 를 자체 개발했다는 점입니다.

- 카카오톡, 인스타그램 DM, 메모장, 검색창 — **어떤 앱에서든** 사용자가 음식 이름을 입력하면 키보드 위에 영양 등급이 즉시 표시됩니다.
- 기존 앱처럼 "GluCoach 앱을 켜고 검색"하는 단계가 사라집니다. 의사결정 흐름에 가장 자연스럽게 녹아듭니다.

### ② 식약처 표준 데이터 기반의 신뢰성

- 음식 영양 정보는 **식품의약품안전처 공공 식품영양성분 DB**(전국 약 4만 건 이상)를 기반으로 자체 구축했습니다.
- 운영 중에는 외부 API에 의존하지 않아 응답 속도가 빠르고, 외부 서비스 장애 영향을 받지 않습니다.
- "이 등급의 근거는 무엇인가?"에 대해 식약처 공인 영양성분 수치로 답할 수 있습니다.

> **GluCoach 등급(S~D)이 뜻하는 것**
> 등급은 그 음식을 먹었을 때 **식후 혈당이 얼마나 가파르게 오르는지**를 예측한 결과입니다.
> **S(가장 완만, 가장 안전) → A → B → C → D(가장 가파름, 가장 위험)** 의 5단계로,
> 등급이 높을수록 혈당 상승 곡선이 완만해 당뇨 관리자에게 친화적인 음식입니다.

### ③ 세 종류의 AI 협업

| AI 종류               | 역할                                                                  | 사용 기술 (참고)                              |
| --------------------- | --------------------------------------------------------------------- | --------------------------------------------- |
| **음식 사진 인식 AI** | 사용자가 찍은 음식 사진을 자동 인식해 식사 기록·등급 산정까지 한 번에 | 자체 학습한 **EfficientNet-B0** + 임베딩 검색 |
| **숫자 판단 AI**      | 음식의 혈당 상승 기울기 등급(S~D) 산정, 식후 혈당 곡선 예측           | 머신러닝 (XGBoost, PyTorch)                   |
| **대화형 AI 비서**    | "오늘 컨디션 어때?", "뭐 먹을까?" 자연어 추천                         | Claude (Anthropic) · OpenAI                   |

빠른 판단은 가벼운 모델이, 깊이 있는 추천은 대화형 LLM이 맡습니다. 사진 인식은 외부 API에 의존하지 않고 **GluCoach가 직접 학습한 자체 모델**로 동작합니다.

> **사진 인식이 단순한 분류가 아닌 이유**
> 일반적인 사진 인식 앱은 "사진 → 음식 종류 한 개" 분류기로 작동합니다. GluCoach는 **임베딩 검색** 방식을 채택해, 사진을 의미 벡터로 변환한 뒤 식약처 음식 DB와 가장 가까운 후보를 검색합니다.
> 결과적으로 **신규 음식·지역 음식·메뉴 변형**이 등장해도 모델을 다시 학습할 필요 없이 DB에 prototype 한 장만 추가하면 즉시 인식 가능합니다. 운영 비용과 확장성 모두 유리한 구조입니다.

### ④ 음성 비서 "키키" — 손이 자유롭지 않을 때

- 운전 중, 요리 중, 운동 중처럼 핸즈프리가 필요한 순간을 위해 음성 비서 **"키키"** 가 탑재되어 있습니다.
- "하이 키키" 한 마디로 깨우고, "나 뭐 먹을까?"라고 물으면 그날의 혈당 추세·점심 패턴·시간대를 종합해 추천합니다.

## 3. 어떻게 쓰는가 — 핵심 사용 장면

> **장면 1**은 사용자가 매일 가장 자주 마주하는 메인 화면(대시보드) 흐름이고, **장면 2~4**는 일상의 결정 순간마다 GluCoach가 어떻게 끼어드는지를 보여주는 보조 시나리오입니다.

### 🎬 장면 1. 아침에 일어나, 어제의 혈당·식사·조언을 한눈에 (메인 대시보드)

```
출근 준비 중 → GluCoach 앱 열기
   └─ 메인 대시보드 한 화면:
       · 어제 하루 혈당 곡선 (식사 시점이 점으로 함께 표시)
       · 점심 "비빔밥", 저녁 "치킨" — 각 식후 피크값과 등급
       · AI 비서 키키의 한마디:
         "어제 저녁 치킨 이후 혈당이 평소보다 30 더 올랐어요.
          오늘 점심은 조금 가볍게 가시는 게 어떨까요?"
```

- **누가**: 1형 당뇨를 7년째 관리 중인 30대 직장인
- **어디서**: 매일 아침 출근 전, 잠시의 휴식 시간
- **가치**: 흩어져 있던 혈당값·식사 기록·전문가 조언을 **한 화면에서 동시에** 파악. 별도 다이어리·노트·진료 기록을 뒤질 필요가 없음

### 🎬 장면 2. 친구가 갑자기 "마라탕 ㄱ?"이라고 했을 때

```
친구: "오늘 점심 마라탕 ㄱ?"
당신: 카톡에 "마라탕" 타이핑
   └─ 키보드 상단: 🔴 D등급 (혈당 상승이 가파른 음식, 주의)
당신: "마라탕 말고 다른 거 어때?"
```

- **누가**: 당뇨 전단계인 30대 직장인
- **어디서**: 점심시간 직전, 동료 단톡방
- **가치**: 사회적 어색함 없이, 자연스러운 채팅 흐름 안에서 더 나은 선택

### 🎬 장면 3. 식당에서 음식 사진 한 장으로 — 식단 기록·등급·혈당 예측 한 번에

```
식당에서 막 나온 음식을 사진 한 장 촬영
   └─ GluCoach가 자동으로:
       · 음식 종류 인식 (EfficientNet 기반 임베딩 검색)
       · 식약처 영양 DB 매칭 → 등급(S~D) 표시
       · 식후 2시간 혈당 곡선 예측 그래프
       · 식단 기록에 자동 저장 (수기 입력 불필요)
```

- **누가**: 외식·출장이 잦은 40대 당뇨 환자
- **어디서**: 처음 가본 식당, 메뉴명이 익숙하지 않은 음식 앞
- **가치**: 메뉴명을 몰라도, 검색이 까다로워도 **사진 한 장**이면 끝. "오늘 뭐 먹었는지"를 매일 손으로 적을 필요가 사라짐

### 🎬 장면 4. 운전 중에 점심 추천을 받을 때

```
운전 중:
당신: "하이 키키"
키키: "네, 주인님"
당신: "나 뭐 먹을까?"
키키: "오늘 아침 혈당이 평소보다 높았고, 점심 시간이라
       탄수화물 부담이 낮은 그릴드 치킨 샐러드를 추천드려요."
```

- **누가**: 출장이 잦은 50대 당뇨 환자
- **어디서**: 운전 중, 식사 장소를 정해야 하는 순간
- **가치**: 화면 조작 없이, 본인의 누적 데이터를 반영한 맞춤 추천

## 4. 기술 구성 — 한눈에 보는 시스템

### 4-1. 시스템 흐름

```
              [사용자 — 안드로이드 앱]
                       │
                       │  HTTPS (암호화 통신)
                       ▼
              [공개 진입점 (nginx)]
              SSL 처리, 트래픽 분배, 보안 차단
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   [백엔드 API]    [AI 서비스]    [워크플로우 엔진]
   Spring Boot     FastAPI        n8n
   회원·식단·      사진 인식·     보호자 알림 등
   혈당 관리       등급 산정·     자동화
        │          혈당 예측·
        │          대화형 추천
        │              │
        └──────┬───────┘
               ▼
        [데이터 저장 계층]
        · PostgreSQL                — 식약처 영양 DB + 사용자 이력 영구 보관
        · Redis                     — 자주 조회되는 정보의 빠른 캐시

        [외부 연동]
        · AWS S3                    — 사용자 음식 사진 저장소
        · Anthropic Claude / OpenAI — 자연어 답변 생성
        · Firebase FCM              — 보호자 푸시 알림 전송
```

### 4-2. 구성 요소

| 구성 요소   | 사용 기술                                                     | 역할                                              |
| ----------- | ------------------------------------------------------------- | ------------------------------------------------- |
| 모바일 앱   | Kotlin · Jetpack Compose                                      | 사용자 화면 + 키보드 IME + 음성 비서 "키키"       |
| 공개 진입점 | nginx                                                         | HTTPS 보안 종단, 트래픽 분배, 보안 차단           |
| 백엔드 API  | Java 21 · Spring Boot 3.5                                     | 회원·식단·혈당·알림 데이터 관리                   |
| AI 서비스   | Python · FastAPI · PyTorch · EfficientNet(자체 학습) · Claude | 음식 사진 인식, 등급 산정, 혈당 예측, 자연어 추천 |
| 워크플로우  | n8n                                                           | 보호자 알림, 정기 리포트 등 반복 업무 자동화      |
| 데이터 저장 | PostgreSQL 17                                                 | 식약처 영양 DB + 사용자 이력 영구 보관            |
| 캐시        | Redis 7                                                       | 자주 조회되는 정보의 빠른 조회                    |
| 외부 연동   | AWS S3 · Anthropic Claude · OpenAI · Firebase FCM             | 사진 저장 · 자연어 답변 · 푸시 알림               |

### 4-3. 운영 안정성

- **무중단 배포 (Blue-Green 방식)**: 새 버전을 별도 서버 슬롯에서 미리 띄워두고, 헬스 체크를 통과하면 트래픽을 1초 내에 새 슬롯으로 전환합니다. 사용자가 업데이트를 체감하지 못합니다.
- **자동 SSL 인증서 갱신**: HTTPS 인증서 만료 전 시스템이 자동으로 새 인증서를 발급·교체합니다.
- **데이터 백업 절차 마련**: 식약처 영양 DB와 사용자 이력은 영구 저장소에 보관되며, 정기 백업이 가능한 구조입니다.
- **장애 시 즉시 롤백**: 새 버전에 문제가 발생하면 약 60초 이내에 이전 슬롯으로 트래픽을 되돌릴 수 있습니다.

## 5. 향후 확장 / 사업화 포인트

### 5-1. B2C — 헬스케어 구독 모델

- **기본**: 무료 (음식 검색·등급 표시·기본 추천)
- **프리미엄**: 개인 맞춤 식단 리포트, 보호자 알림, AI 비서 무제한, 누적 데이터 분석
- **타겟 사용자 수 추정**: 국내 당뇨/전단계 인구만 약 1,500만 명 + 임신성 당뇨 + 다이어트·헬스 관리 인구

### 5-2. B2B — 데이터·플랫폼 제휴

| 파트너 유형         | 협업 가치                                                                       |
| ------------------- | ------------------------------------------------------------------------------- |
